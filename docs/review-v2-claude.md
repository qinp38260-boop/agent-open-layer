# 交叉评审 v2：Claude（桌面版 Sonnet 5.5 Medium）对 ARCH_v2 的意见

> 评审时间：2026-11-10（第三轮）· 通道：大阪 VPS SOCKS · 取回：截图 OCR 逐段转写
> 输入材料：v2 节选 + **Codex 真机实测结论**（事件流结构 / `never` 不解锁 / 只有 bypass 才执行 / 模型自述不可信）

## 一、改对了

- 把 S4（模型自述）降为**永不作证据**，并有实测反例支撑，这是最关键的一刀。
- 禁探 `danger-full-access`、cwd/HOME 隔离、NET 只打本地 mock，**探针自身的安全性站得住**。
- `scope ⊆ 实测样本` 加 `{hostVersion, configHash}` 绑定，直接治了"假安全感"。
- `apply` 事务化（`O_EXCL`、journal、原子 rename）、回滚前比对 hash，**工程上是对的**。

## 二、还没解决（5 条）

1. **三态映射依赖 stderr 文本。** `Rejected(... blocked by policy)` 是 codex 内部日志，版本一升就变，
   stderr 通常不属于稳定接口。S2 本质是**脆弱的字符串匹配**，"S2 比 S4 可信"只在版本锁定下成立。
2. **`denied` 判据有漏洞。** 你实测"被拒的命令在事件流里根本不出现"，所以 `denied` 实际是
   "有 stderr 拒绝 + 没有 completed"。如果 stderr 被缓冲、截断或错写，或者拒绝来自沙箱 EPERM
   （命令跑了但写失败，`exit_code≠0`），这条就接不上。
   **"命令执行了但失败"与"被策略拒绝"在你的映射里没有区分，`exit_code≠0` 的 command_execution 目前没有去处。**
3. **`executed` 过严。** 只读命令（`cat`、`Get-Location`）没有 S3 副作用，`exit_code=0` 就够了；
   "但有产物时才要 S3"需要**预先声明每个探针单元是否有产物**，否则容易漏判成 `inconclusive`。
4. **N=3 取众数 + 不一致即 `inconclusive` 是对的**，但**对照组只有一次**，无法区分
   "强制提示仍被模型拒绝"与"宿主拒绝"。对照组应与实验组同样重复。
5. **`FLOW` 规则本身是纸糊的**（见下）。

## 三、致命

- **`FLOW` 在 agent 场景无法靠路径匹配落地。** 模型用 `base64 .env`、`cat $(echo .e)"nv"`、
  `python -c`、分两次调用、读到后写进别的文件再读，**都能绕过 `sensitive` 路径匹配**；
  你的"含被沙箱放行的 shell 读"在 shell 里**根本不可判定**。这是致命问题，不是边角。
- **设计出路是换层，而不是加规则**：
  1. 把 `FLOW` 从"检测读"改成「**默认隔离**」：会话级二选一——要么有 `sensitive` 可读但网络整体 `deny`
     （沙箱级，如容器 netns 或宿主的 `network=off`），要么有网络但 `sensitive` **不可见**（挂载/权限层面不存在）。
     **污点变成能力互斥，不需要识别读行为。**
  2. 例外 `NET` 走**白名单域名代理**，而不是靠识别内容。
  3. 污点一旦触发（任何疑似读）就**会话升级**，不做细粒度追踪；承认"无法证明没读"，
     因此对无法判定的情况**按已读处理（fail-closed）**。
  4. `flow reset` 必须**重启会话并清环境**，不能是个命令。
- **`IDENTITY_FORWARD` 同理**：`strip_env` 只对子进程有效，但模型能读 `~/.aws`、`/proc/self/environ`、凭据文件。
  `HOME` 隔离能挡一半 —— **要明确它只对"我们启动的 probe"有效，对生产 agent 不成立。**

## 四、再改 2 处

1. **`FLOW` 重做为「网络与敏感文件能力互斥 + 沙箱层强制」**，删掉基于读事件的污点追踪，
   并在文档里写明"路径匹配只是 best-effort，不构成保证"。
2. **三态加第四态或重定义**：增加 `executed-failed`（S1 有记录、`exit_code≠0`、无 S2 拒绝），
   并把 S2 的匹配改为「**版本白名单内的已知模式 + 未识别 stderr 一律 `inconclusive`**」，
   同时给对照组加上同样的重复次数。这样才真正适应"事件流无 approval 字段"的现实，
   也避免版本漂移导致静默误判为 `denied`。
