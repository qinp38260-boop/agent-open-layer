# 交叉评审 v1：Claude（桌面版 Sonnet 5.5 Medium）对 ARCH_v1 的意见

> 评审时间：2026-11-10（第二轮）· 通道：大阪 VPS SOCKS 隧道 · 取回方式：截图 OCR + 粘贴
> 原文要点摘录（未改写），逐条处置见文末。

## 改对了（3 条）

- 审批轴/边界轴拆开、`deny > ask > allow` 与声明顺序无关、未命中=不写配置，方向正确。
- 断言改为探针证据、并写入 `hostVersion`，**这是质变**。
- hook 失败显式 deny、`baseHash` 防竞态、argv 解析，均落到了具体机制。

## 还错（4 条）

**1. 缺维度**

- **数据流向**：`READ` 与 `NET` 各自合规，但"读 `.env` 再 POST"组合起来就泄密。
  需要污点或会话级规则，至少加「`READ(敏感路径)` 之后禁 `NET`」。
- **身份转发**：子进程继承的环境变量、凭据、`ssh-agent` 没有建模。
- 频次/时间：只做 `ask` 的超时即可，其余可后置。

**2. 三结局判定不可靠**

- "看产物是否被改"只对 `WRITE`/`EXEC_DESTRUCTIVE` 有效；对 `EXEC_SAFE`、`NET`、`READ` 没有产物，
  **无法区分"执行了"和"模型自己放弃了"**。
- 最大误判：**模型自行拒绝与宿主 `deny` 无法区分**。拒绝措辞是模型生成的，**不是宿主信号**。
- `exec` 模式下 `ask` 通常直接失败或被自动拒绝，"被问"与"被拒"可能表现一致。
- 单次采样有非确定性；金丝雀 `rm -rf` 可能被模型改写成别的命令。

**3. fail-closed 漏洞**

- `apply` 中途崩溃（断电/SIGKILL）时，§7.8 的"立即回滚"**根本不会执行**，需要 journal / WAL，
  下次启动先检测残留并恢复；对备份做 hash 比对，不一致就停下报警。
- **hook 被杀**：超时只有 hook 自己能处理，进程被强杀时宿主侧无任何记账。

**4. 规则与 probe 的粒度不匹配**

- probe 只验证了金丝雀**这一个点**，却被推广为整个 scope 的结论。

## 会出事（4 条）

- **最大隐患：probe 证据的有效期。** 它只证明"这个版本、这个配置、这个 cwd、这一次"的行为，
  规则却按 scope 泛化（`workspace/**` 实际只测了一个路径）。写后再 probe 同样只是抽样，
  会给人"已验证"的**假安全感**。
- **probe 本身有副作用**：沙箱探测一旦逃逸（`danger-full-access` 下的 `rm -rf`），会真删东西。
  必须强制 cwd 与 HOME 隔离，**且不得探测 `danger-full-access`**。
- **版本漂移**：宿主自动升级后，旧 probe 报告仍被当作证据。
- **"auto-revert" 本身是写操作**，失败路径最少被测，最容易出事。

## 再改 3 处

1. **probe 改为"宿主信号优先"**：优先读宿主结构化事件（`Codex exec --json` 事件流里的 approval/exec 记录），
   而不是从产物和措辞反推；每个单元重复 N 次，并加一个"强制模型照做"的对照组。
   **无结构化信号的单元一律标 `inconclusive`，不得当 allow 用。**
2. **证据绑定与过期**：每条规则记录 `{hostVersion, configHash, 实测 scope 样本}`；
   apply 时 version 或 configHash 不一致即视为无证据（`UNVERIFIED_RULE`）。
   泛化规则只能覆盖已测样本，其余走宿主默认。
3. **apply 事务化**：加锁（`O_EXCL lockfile`）→ 写 journal → 备份并记 hash → 临时文件 + 原子 rename →
   清 journal。启动时发现 journal 就先恢复或提示。回滚前先比对当前 hash，被外部改过就不覆盖，
   只输出人肉步骤。
