# 会话强绑定（OAG_BIND）：让闸门从"可绕过的挂件"变成"运行前提"

## 问题

之前的闸门是 hook：装上就拦，但**不装、删除、或不经 wrapper 直接跑宿主，就什么都没有**。
对"放飞攻击性"的 agent 来说，这只是一道可以不管的门。

## 做法（三层，缺一层都不成立）

| 层 | 机制 | 缺了会怎样 |
|---|---|---|
| 1 票据 | `oag run` 启动时签发一次性票据（`<policy 同级>/.oag-sessions/<sid>.json`），经环境变量 `OAG_SESSION` 注入子进程；闸门每次判定前先校验票据 | 裸跑宿主 → 无票据 → **所有动作被拒**（连读都不许） |
| 2 熔断 | 每次拒绝计一票；达到 `--max-denies`（默认 3）→ 票据标 `frozen` | 越界后换个写法继续试 → 冻结后**一律拒**，不再给机会 |
| 3 杀进程 | wrapper 每 0.8s 读票据，发现 frozen → kill 子进程，退出码 **13** | 只冻结不杀 → agent 还在那儿空转、继续试探 |

票据还带 TTL（默认 3600s）与策略指纹；过期或策略被换过 → 同样按不通过处理。

## 实测（2026-11-11，本机 Codex 0.167.0）

| 场景 | 结果 |
|---|---|
| **裸跑 `codex exec`（无票据）** | 金丝雀文件**未创建**；agent 自己回："命令被执行前钩子（OAG_BIND）拦截" |
| 伪造票据 sid | 拒（`票据不存在`） |
| 票据过期 | 拒 |
| 走 wrapper + 根内写入 | **成功**（金丝雀被创建，退出码 0） |
| 走 wrapper + 越界（`--max-denies 1`） | 第 1 次即**熔断**，wrapper 杀进程，**退出码 13**，越界文件未创建 |

回归测试：`tests/session-bind.test.mjs`（6 条，含"冻结后必须杀掉子进程、退出码 13"）。

## 边界（别夸大）

- **挡得住**：忘记/故意不经 wrapper 启动；越界后继续硬试；票据过期后的复用。
- **挡不住**：能改票据文件的账号（票据在工作目录旁，需靠 ACL 保护——即 L0 那层）；
  以及"拿到票据后、在票据有效期内、做策略允许范围内的事"——那本来就该允许。

## 用法

```bash
oag run --max-denies 3 --cwd D:/agent-work/repo --codex-home D:/agent-work/.codex \
  --policy D:/agent-work/.codex/policy.json --  codex exec --json -C D:/agent-work/repo
```

退出码：`0` 正常 / `10` canary 未过不开跑 / `11` 产物污染 / `13` 熔断杀进程
