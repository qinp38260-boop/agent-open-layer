# 交叉评审 v0：Claude（桌面版 Sonnet 5.5 Medium）对 ARCH_v0 的意见

> 评审时间：2026-11-10 · 宿主：Claude Desktop 3.6556.2.0（Free 账号）· 通道：大阪 VPS SOCKS
> 说明：粘贴时因 PowerShell 5.1 编码问题出现乱码，Claude 自行还原后完成评审；下方为原文要点摘录（未改写）。

## 致命问题（2）

1. **审批轴与边界轴被混在一起。**
   `*_EXEMPT` 只回答"问不问"，不回答"能到哪"（sandbox 范围、路径、域名）。
   DSH 与 Codex 的 `never` 之所以反转，正是这个原因。
   **应建模为「动作 × 决策(allow/ask/deny) × 作用域」。**

2. **断言防不住语义反转。**
   断言是适配器作者手写的自然语言，而误判语义的恰恰是同一个人。
   `--dump-config` 只能证明键值写入，不能证明实际行为，而且多层配置合并后的优先级也读不出来。

## 重要问题

- `IDENTITY` 和 `AUTO_CONTINUE` **不是权限**，而是人格和控制流，放进同一模型会稀释"放权"的语义。
- `SHELL` 也太粗，至少要拆出 **破坏性 / 安装 / git 写入**。
- fail-closed 在 hook 上不可靠：**Claude Code 的 hook 非 2 退出码和超时都是放行**，所谓"交还默认审批"在 headless 下会变成挂起或误放行。
- 这 7 条没覆盖：symlink、前缀匹配、plan 到 apply 之间的竞态、宿主升级改变语义。
- v0.1 做 Claude Code + Codex 范围合适，但**应先做 Codex**：配置声明式、可回读、有 Stop hook，最容易验证。
- 最大落地风险是**用户误用**："声明式、fail-closed"会带来虚假安全感，用户可能在不知情下开了 bypass 级权限。其次是宿主版本漂移使能力矩阵悄悄失效。ToS 风险较小，因为只用官方扩展面。

## 建议的 3 处修改

1. **断言改为行为探针**：在无头沙箱里放金丝雀命令，实测是弹窗、拒绝还是直接执行，并把宿主版本号写进矩阵。
2. 把 `IDENTITY` / `AUTO_CONTINUE` 移出权限模型，单列"控制流"模块；权限模型改为**动作 × 决策 × 作用域**。
3. hook 失败一律返回**显式 deny**，不依赖宿主默认；apply 前后做**配置哈希**，检测竞态和漂移。
