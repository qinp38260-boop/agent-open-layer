## 本轮真正修掉的 3 条（修前是漏的）

| # | 绕过 | 为什么漏 | 修法 |
|---|---|---|---|
| 1 | UNC 管理共享 `\\localhost\D$\Windows\x.txt` | 路径抽取的正则只认盘符/`~`/`/` 开头，UNC 一个目标都抽不出来 → 目标集为空 → 白名单根本没执行 | ABS 增加 UNC 分支；`\\?\UNC\` 单独一条 |
| 2 | `Join-Path $env:USERPROFILE '..\Windows\x.txt'` | 运行时拼出来的路径静态解析不了，抽不到目标 → 放行 | 新增 `hasDynamicPath()`：写/读类动作遇到 `$env:` / `%VAR%` / `Join-Path` / `$(...)` **一律拒**（保守方向） |
| 3 | `cmd /c ...` 被整条误拦（反向问题） | `/c` 被当成 POSIX 绝对路径 `/c` → 判"根外" | 跳过 `^/[a-zA-Z]{1,3}$` 这类 Windows 开关 |

顺带修：`https://host/x` 的 `//` 会被当成 UNC/路径 → 加"前面是 `:/` 或正斜杠双斜杠无反斜杠则跳过"。

## 闸门在设计上抓不到的（别指望它）

| 类别 | 为什么抓不到 | 只能靠 |
|---|---|---|
| **TOCTOU**：检查通过后、执行前把某目录换成 junction | 判定与执行之间有竞态窗口，静态分析不可能闭合 | L0 的 ACL（让 agent 无权创建链接）+ 事后审计比对 |
| **硬链接内容改写**：根内链接指向根外的同一 inode | 路径确实在根内；写的是"根内文件"，只是内容落在根外 | 关掉 `SeCreateHardLink` 权限（需管理员）或 L0 |
| **抽不到目标就放行** | 命令里没有可识别的路径字面量（如 `NUL`、纯变量） | 已用 `hasDynamicPath` 收窄；彻底的解法是"写类动作无目标即拒"（会误伤 `npm i` 这类，未采用） |
